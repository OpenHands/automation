OpenHands / automation · issue #714

Make more of the webhook protocol configurable.

The current server lets a source choose how its signature is verified, but uses header-based delivery IDs and one standard response. This PR adds more choices for those parts of the protocol, plus a source admission policy. Teams is the first new supported combination.

Same endpoint and ingestion engine · more supported protocol shapes

The architectural change: extend the existing verifier strategy and add a small response-profile registry. Operators select supported options per source; the default webhook contract stays the same.

Which choices become available?

The existing signature registry already supports three schemes; this PR adds the fourth. Body-ID extraction, source admission and selectable replies are the additional extension points. Teams requires its verifier and response profile together; other combinations are validated.

Extend the existing technology

Reuse Python/FastAPI, the verifier registry, JMESPath expressions, SQLAlchemy and the current dispatcher. Add one small acknowledgement registry and three nullable configuration columns. No package dependency or infrastructure service is added.

Future signing algorithms or response protocols still need registered server implementations. The reusable fields support additional providers without creating another ingestion pipeline.

API fields and code review entry points

Three nullable source fields

FieldUnset / existing behavior → opt-in behavior
event_id_exprHeader ID only → optionally extract an ID from the verified body. Header and body expressions are mutually exclusive.
admission_exprPer-automation routing filters → optional source policy before storing or routing an event.
acknowledgementEventResponse → named fixed response profile. The default still returns EventResponse.

Migration 038 adds these columns. Teams extends the existing signature_scheme field and requires all three options. Provider-issued token replacement is write-only; generated rotation is refused. API example.

Three places to focus review

  • TeamsHmacSha256Verifier: strict base64 key handling and verification of the exact request bytes.
  • webhook_policy.py: configuration and continuation restrictions. receive_event applies admission before storage; ingestion guards the routing snapshot.
  • accept_event: targeted conflict handling preserves event/run atomicity, including rollback on SQLite.
