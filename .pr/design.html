Issue #342 · Phase 1

Make every automation run identify its source

A run now records the tarball selected for execution and, when trustworthy, the Git commit that produced it. Historical run data no longer changes meaning when the automation is edited later.

PostgreSQL + SQLiteBackward-compatible APINullable provenance

The missing link

01

Mutable definition

The executor previously read automation.tarball_path. Once that row changed, a historical run could not prove which source it launched.

02

Potentially stale Git SHA

last_synced_commit is only valid while Git sync state is clean. Recording it after a DB-side edit would claim provenance the system cannot support.

Before / after

Design decisions

Freeze at claim time

Creation initializes the fields for immediate visibility. Dispatch refreshes them in the transaction that moves the run to RUNNING, preserving existing “latest definition at dispatch” behavior while making the recorded source match execution. See the claim path.

Trust only clean Git state

A commit is copied only where dirty = false. Unsynced or edited automations retain a useful tarball identifier and an honest null commit. See the snapshot helper.

Execute the snapshot

The executor reads run.source_tarball_path. A fallback to the automation row keeps pre-migration pending runs dispatchable. See source resolution.

Keep the migration additive

Both columns are nullable and use generic SQLAlchemy types, so existing rows and both supported databases remain compatible. See migration 023.

Scope and risks

This is phase 1 of issue #342. It makes the executed source observable. Git ref pinning, restore endpoints, rollback policy, and UI are deliberately not included.

Known boundary: this records source provenance, not a full immutable execution configuration. Entrypoint, model, secrets, and runtime dependencies are outside this change. The nullable schema also means older runs cannot be reconstructed retroactively.

Performance: source stamping adds one indexed primary-key lookup of Git sync state per created run and once again at dispatch claim. That second lookup closes the edit-while-pending race.
